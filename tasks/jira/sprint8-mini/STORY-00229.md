# STORY-00229: levels.js / gallery.js / shop.js 适配安全区

**Epic**: E-002 关卡系统 / E-003 道具系统 / E-006 展厅
**Sprint**: Sprint 8-mini
**Sprint Goal**: 刘海屏安全区适配
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player on a notch phone, I want the back button and card grids in levels/gallery/shop to not be hidden behind the notch.

## Expected Result
Back button is always visible below the notch; card grids start below the safe area.

## Acceptance Criteria
- [ ] `levels.js`: back button drawn at `y = G.SAFE_TOP + 14`; `PAD_TOP` calculated as `G.SAFE_TOP + 80`
- [ ] `gallery.js`: back button drawn at `y = G.SAFE_TOP + 14`; `PAD_TOP` calculated as `G.SAFE_TOP + 76`
- [ ] `shop.js`: back button drawn at `y = G.SAFE_TOP + 14`; `PAD_TOP` calculated as `G.SAFE_TOP + 70`
- [ ] Scrollable clip region in each screen starts at `PAD_TOP - N` (same as before, but PAD_TOP now includes SAFE_TOP offset)
- [ ] All `_computeLayout()` calls happen after `initGlobals()` so `G.SAFE_TOP` is available
- [ ] Scroll total height recalculated using new PAD_TOP values so scroll range is correct

## Dependencies
- Depends on: STORY-00226

## Notes
The `PAD_TOP` constants are currently module-level `const` values. They need to be computed inside `_computeLayout()` or `showXxx()` where `G.SAFE_TOP` is already set.
Pattern: `const padTop = G.SAFE_TOP + 80;` (in function, not module-level).
Use the local `padTop` variable instead of `PAD_TOP` const for all layout calculations in that function.
