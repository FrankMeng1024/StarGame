# STORY-00007: 修复失败画面统计数据显示

**Epic**: E-007 关卡完成体验
**Sprint**: Sprint 2
**Sprint Goal**: 完成进度循环 — 玩家能用金币购买道具、在展厅欣赏已解锁的星座
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player who fails a level, I want to see how many stars I caught and how much time elapsed, so that I can understand my performance and feel motivated to retry.

## Expected Result
When the timer runs out and the fail screen shows, it displays the actual number of stars caught (e.g. "3/7") and the actual time elapsed (e.g. "72秒"). Currently these show as "—" and "0秒".

## Acceptance Criteria
- [ ] Fail screen displays actual caught star count (e.g. "已抓: 3 / 7 颗")
- [ ] Fail screen displays actual time elapsed in seconds (e.g. "用时: 72秒") — calculated as (timeLimit - timeLeft)
- [ ] Both values are non-zero when the player has caught stars and time has elapsed
- [ ] Retry button on fail screen navigates back to the same level (navigate('game', {levelIdx: N}))
- [ ] "返回选关" button navigates to level select
- [ ] Values correctly reflect a fresh game where no stars were caught (0/7, 90秒)
- [ ] UX: fail screen stats are visually clear and do not feel like error/debug output

## Dependencies
- Depends on: STORY-00003 (game engine emits timeLeft/caught on fail), STORY-00004 (fail screen render)
- Blocks: none

## Notes
Root cause from Sprint 1 UX review: fail screen was being shown without passing actual game state (caught, timeLeft). The onFail callback in engine.js likely passes these values — verify and wire them through to the fail screen render function.
