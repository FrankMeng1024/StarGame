## Description
As a player, I want to scroll through the level selection screen to see all 30 levels.

## Expected Result
Touch drag on level select scrolls smoothly. All 30 levels are reachable on real device.

## Acceptance Criteria
- [ ] Touch scroll works on real device — dragging down shows lower levels
- [ ] DPR correction applied: `dy` divided by `wx.getSystemInfoSync().pixelRatio` (or equivalent) before being used as scroll offset
- [ ] Scroll direction correct: drag up = scroll down (see more levels), drag down = scroll up
- [ ] No erratic jumping or over-scrolling
- [ ] All 30 level cards reachable by scrolling
- [ ] Momentum scroll still works (velocity tracking preserved)

## Root Cause
levels.js uses `touch.clientY` directly for dy, but in WeChat Mini Game, `clientY` is in CSS/logical pixels.
The canvas coordinate system uses physical pixels (canvas.width/height = logical * DPR).
On a DPR=3 device (e.g. iPhone 14), dy is 3x too large, causing erratic scroll jumps.
Fix: divide dy by the system pixelRatio when computing scroll delta.

## Notes
wx.getSystemInfoSync().pixelRatio gives device pixel ratio.
Alternatively, use `touch.x` instead of `touch.clientY` if wx reports touch.x in canvas coordinates.
Need to check what coordinate space WeChat mini game touch events actually use.
