# STORY-00114: 精灵图全时段即时渲染 — 解锁关卡预热 + 通关时预热下一关

**Epic**: E-011 性能优化
**Sprint**: Sprint 23
**Sprint Goal**: 2项游戏体验修复
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, I want level 1 (and any level) to start instantly regardless of when I click it — even if it's the very first thing I do after opening the app. I should never see a blank canvas or loading delay on level entry.

## Expected Result
Level entry renders sprites immediately on the first frame, for all levels, at any point in the session.

## Acceptance Criteria
- [ ] `initLevels()` calls `prewarmSprites()` and awaits it before enabling level card click handlers — level cards become clickable only after sprites are confirmed complete
- [ ] A `prewarmSprites()` function is exported from `levels.js` that returns a Promise resolving when all 6 sprite SVGs are `complete` (uses `img.decode()` on each cached Image)
- [ ] `_handleComplete` in `game.js` calls `prewarmSprites()` after navigating to the complete screen — so sprites are re-confirmed ready for any subsequent level entry
- [ ] Level 1 clicked immediately after app open: canvas renders character and net from the first frame, no blank canvas
- [ ] Level 1 clicked after completing level 2: same instant render — no regression

## Root Cause
`_prewarmAssets()` IIFE starts loading 6 SVG sprites at module load, but does NOT wait for completion. If the user clicks level 1 within ~1-2 seconds of page load (before `img.complete` becomes true), `getSpriteReady()` must wait for the `load` event — causing the visible delay. Levels 2+ appear instant because level 1 takes 60-90s to play, giving sprites time to fully load.

## Fix
1. Export `prewarmSprites()` from `levels.js` — returns `Promise.all` of `decode()` for all 6 cached sprite Images
2. In `initLevels()`: call `prewarmSprites()`, add a loading state (show level cards slightly dimmed or with a brief spinner), enable click handlers only in `.then()`
3. In `game.js` `_handleComplete`: fire `prewarmSprites()` (non-blocking, best-effort) so sprites are warm before user can navigate to the next level
