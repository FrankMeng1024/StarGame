# STORY-00018: 音效系统 — Web Audio API procedural sounds

**Epic**: E-001
**Sprint**: Sprint 5
**Sprint Goal**: 感官完整度 — 音效与反馈polish
**Points**: 3
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a player, I want to hear satisfying sound feedback when I catch stars, hit debris, complete a level, or run out of time, so that the game feels alive and responsive.

## Expected Result
Key game events trigger short procedural audio cues generated via Web Audio API (no external files). Audio respects a global mute toggle accessible from the game screen.

## Acceptance Criteria
- [ ] Star catch: short ascending tone (e.g. 880Hz, 80ms, sine wave, volume 0.4)
- [ ] Debris catch: short descending buzz (e.g. 220Hz, 120ms, sawtooth wave, volume 0.3)
- [ ] Level complete: short 3-note ascending fanfare (do-mi-sol, 150ms each)
- [ ] Countdown warning (≤10s): low pulse beep every 2s (100Hz, 60ms, square wave)
- [ ] Time extension used: brief whoosh tone (400→800Hz sweep, 150ms)
- [ ] Mute button in game HUD — persisted in localStorage key 'starcatcher_muted'
- [ ] No audio errors in browser console
- [ ] Audio does not play if tab is backgrounded / audio context suspended

## Dependencies
None

## Notes
Use Web Audio API AudioContext directly. No external library. Create AudioContext lazily on first user interaction (Chrome autoplay policy).
