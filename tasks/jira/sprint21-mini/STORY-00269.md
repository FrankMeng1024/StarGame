# STORY-00269: 移除错误的DPR触控乘数 — 按钮点击修复

**Epic**: E-005 核心游戏体验
**Sprint**: Sprint 21-mini
**Sprint Goal**: 修复真机3个Blocker：按钮无法点击+黑屏扫码+首页按钮视觉优化
**Points**: 3
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, I want all buttons on all screens to respond to my taps, so that I can navigate the game normally.

## Expected Result
All touch interactions (menu buttons, level grid, shop items, gallery scroll, achievement scroll, in-game controls) register correctly on real device with DPR ≠ 1.

## Acceptance Criteria
- [ ] All 6 screen files (menu.js, levels.js, game.js, gallery.js, shop.js, achievement.js) have touch.clientX/Y used directly without `* G.DPR` multiplication
- [ ] Menu START/LEVELS/GALLERY/SHOP buttons all respond to tap
- [ ] Level grid taps register correct level selection
- [ ] In-game net throw responds to tap
- [ ] Gallery and shop scroll responds to drag
- [ ] Achievement scroll responds to drag
- [ ] Zero console errors related to touch handling

## Root Cause
Sprint 20 incorrectly added `* G.DPR` to all touch handlers assuming canvas = physical pixels.
Reality: `canvas.width = sysInfo.windowWidth` (CSS logical pixels). `touch.clientX/Y` is also in CSS logical pixels. No conversion needed. The `* G.DPR` (e.g. ×3) inflates touch coords to 1125px on a 375px canvas — all hitTests fail.
