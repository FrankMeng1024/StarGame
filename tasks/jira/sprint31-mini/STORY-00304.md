# STORY-00304: 通关界面精简 — 不超边界 + 3按钮布局

**Epic**: Mini端真机质量修复
**Sprint**: Sprint 31-mini
**Sprint Goal**: 通关界面体验全面修复
**Points**: 3
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, when I complete a level, I want the victory card to fit within the screen and show only the essential buttons, without overflowing or cluttering the UI.

## Expected Result
通关结算卡：完全在屏幕内显示，不超出边界。按钮精简为3个（下一关、重玩、选关），去掉"去商店"和"看展厅"两个次级按钮。

## Acceptance Criteria
- [ ] **不超边界**: 结算卡底部不超过屏幕底部（cardY + cardH < H - 10）
  - 修复: cardH计算需考虑lore分页区域实际高度；当内容超出时截断lore文字区域，不撑大卡片
  - 实机横屏(H≈390px)下，结算卡内全部内容可见
- [ ] **精简按钮**: 胜利结算卡只有3个按钮行：下一关/重玩/选关（各占1/3宽度）
  - 删除"去商店"(btnShop)和"看展厅"(btnGallery)次级按钮行
  - 失败结算卡：重试/选关（2个按钮）
- [ ] Playwright截图：胜利卡完整显示，3按钮清晰可见，不溢出屏幕
- [ ] 对比web版complete.js：按钮数量和布局对齐（web版：下一关+商店+选关 = 3按钮）
- [ ] 所有按钮点击导航正确：下一关→game, 重玩→game, 选关→levels

## Notes
当前问题：cardH = Math.min(460, H-20) 在横屏H=390时为370px，但内容（headline+icon+rating+coins+photo+lore+pagenav+buttons+shopgallery）实际需要超过370px，导致按钮被裁剪或溢出。

修复策略：
1. 去掉5按钮（添加了sec row），只保留3按钮
2. 动态计算内容高度，cardH=min(实际内容H+margins, H-20)
3. lore区域高度上限固定为60px（约3行），不随内容动态增长
