## Description
As a player, I want the mini game's HUD, navigation, and screen transitions to match the web version's quality, so that the overall experience feels cohesive and polished.

## Expected Result
HUD elements don't overlap. Screen navigation has a fade transition. Level select has shop shortcut. Back buttons consistent across all screens.

## Acceptance Criteria
- [ ] HUD: pause button positioned at W - G.SAFE_RIGHT - 36, no overlap with timer/star count
- [ ] HUD: timer font 16px, level name font 12px (prevents overlap at H=375)
- [ ] Screen fade transition: on navigate(), canvas fades out (alpha 0→1 black overlay over 150ms), then new screen fades in (black overlay 1→0 over 150ms)
- [ ] Level select: shop shortcut button added at top-right (`W - G.SAFE_RIGHT - 10, G.SAFE_TOP + 10, 72, 32, '🛒 商店'`)
- [ ] Back button style consistent: all screens use `drawButton` with same radius=10, color0='rgba(80,60,140,0.85)', color1='rgba(60,90,180,0.85)'
- [ ] Gallery and Shop: no buttons or text cropped at H=375 (audit: scroll if needed, or reduce font)
- [ ] All 5 screens verified: menu, levels, game, gallery, shop — no overlapping UI elements

## Dependencies
STORY-00280 (menu layout), STORY-00281 (level layout) — implement after those

## Notes
Fade transition implementation: add a module-level `_fadeAlpha = 0` and `_fadeDir = 0` (0=none, 1=out, -1=in). In each screen's render loop, if `_fadeAlpha > 0`, draw `ctx.fillStyle = rgba(0,0,0,_fadeAlpha)` full-screen rect after all content. navigate() sets fadeDir=1, after 150ms calls actual navigate, then fadeDir=-1. 
Since each screen has its own RAF loop, the cleanest approach: add a global fade overlay drawn by the main game.js entry file. Add `let _globalFadeAlpha = 0` to game.js (miniprogram/game.js), increment/decrement each RAF, draw last before requestAnimationFrame. Each screen's _loop calls `drawGlobalFade()` at end.
Actually simpler: implement in canvas-utils.js as `setFadeAlpha(a)` + `drawFadeOverlay(ctx, W, H)`. Each screen _loop calls it at end.
