# STORY-00404: 修复结算页按钮无响应

**Epic**: E-007 游戏体验修复
**Sprint**: Sprint 77-mini
**Sprint Goal**: 修复结算页按钮无响应 + 提升结算/商店UI质量 + 骨骼动画加肉
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, I want the 重试/选关/下一关 buttons on the result screen to respond when I tap them, so that I can continue playing after a level ends.

## Expected Result
Tapping any button on the result/success/fail screen always triggers the navigation within one frame. The 50ms dedup window does not swallow legitimate taps.

## Root Cause Analysis
`_wrapDedup` in globals.js applies a 50ms dedup window per function reference. The tap that skips celebrate/linedraw/linger → result sets the last-fired timestamp. If the player taps again within 50ms (e.g., immediately after the transition), the button tap is swallowed. The dedup was designed to prevent double-fire from dual event sources (wx + canvas.addEventListener), but it fires too aggressively on the result screen.

## Fix
In `miniprogram/js/engine/globals.js`, reduce the dedup window from 50ms to 16ms (one frame). This still prevents double-fire from dual sources (which fire simultaneously) while allowing legitimate sequential taps.

Additionally, in `_onTouch` in game.js, when `_phase === 'result'` and a button is hit-tested, add `_touchLastFired.delete(fn)` equivalent logic — OR expose a `resetTouchDedup()` function that clears the dedup state when entering result phase.

Simplest correct fix: **change dedup threshold from 50 to 16**.
