# STORY-00326: 开场动画流星亮度提升 — 确保流星在截图和真机上可见

**Epic**: Visual Parity
**Sprint**: Sprint 38-mini
**Sprint Goal**: 核心视觉差距修复
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, I want to see spectacular gold meteor streaks from the very first second of the intro animation, matching the impressive visual impact of the web version.

## Expected Result
Screenshots captured at t=4s show bright, clearly visible gold meteor streaks across the dark sky. Constellation reveal phase shows larger, brighter stars with visible sparkle bursts.

## Acceptance Criteria
- [ ] Meteors visible in screenshot taken at t=4s (brightness of meteor area clearly brighter than background)
- [ ] Meteor speed: 7px/frame (was 600-1000px/s — convert: 600px/s ÷ 60fps = 10px/f, reduce to 7 for longer visibility per frame)
- [ ] Meteor trailFactor: 0.40 (was 0.28 — 43% longer trails for more dramatic look)
- [ ] Meteor alpha: minimum 0.92 on new meteors (was 0.85)
- [ ] Meteor lineWidth: 2.5 (was 2.0)
- [ ] Constellation stars: sparkle particle count 8 per star (was 6), radius 3px (was 2px), life 28 frames (was 20)
- [ ] Constellation star glow: shadowBlur=16 when drawn (was implied ~4)
- [ ] Constellation line: lineWidth=2.5 (was 1.2), shadowBlur=10, color rgba(255,215,0,0.75) (was 0.5)
- [ ] 4 meteors with born=0 still present (already implemented — verify unchanged)

## Dependencies
None

## Notes
Root cause of "invisible intro": trailFactor=0.28 means trail drawn with 0.28s lag — at speed ~600px/s that's only ~17px trail length. 
At 7px/frame × 60fps = 420px/s speed, trailFactor=0.40 × 420 = 168px trail = much more visible.
Convert speed: instead of px/s in _spawnMeteor, use px/frame directly in _loop update.
Current update: `m.x += m.vx * dt` where vx = cos(angle) * speed_px_per_sec. Keep this pattern but increase speed to 420.
