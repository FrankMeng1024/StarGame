# STORY-00111: 网绳路径闪烁修复 — 出去和回来路径一致

**Epic**: E-010 游戏体验
**Sprint**: Sprint 22
**Sprint Goal**: 2项游戏体验修复
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, I want the net rope to follow the same path returning as it did going out, so the net feels physically realistic and not jarring.

## Expected Result
When I press Space and the net extends then retracts, the rope's anchor point at the character stays fixed at the throw position throughout the entire extend+retract cycle. No flickering or jumping of the rope path.

## Acceptance Criteria
- [ ] During `netState === 'extend'`: hand position is `(cx+27, cy-78)` — throw frame hand
- [ ] During `netState === 'retract'` with no caught object: hand position remains `(cx+27, cy-78)` — same as extend, no jump
- [ ] During `netState === 'retract'` with caught object: hand position remains `(cx+27, cy-78)` — no jump during catch return
- [ ] Hand position only transitions to idle `(cx+13, cy-17)` when `netState === 'swing'` (net fully retracted, at rest)
- [ ] No visual flicker or path discontinuity visible when net reaches maximum extension and begins retracting

## Root Cause
`_updateHandPos()` in engine.js uses `isThrow = netSt === 'extend'` only. The `else` branch fires during `retract` with no caught object, snapping hand from `(cx+27, cy-78)` to `(cx+13, cy-17)` — a 61px jump that causes the rope to flicker to a different line.

## Fix
Change condition from `isThrow = netSt === 'extend'` to `isActive = netSt === 'extend' || netSt === 'retract'`. Apply throw-position hand coords for full active cycle; idle coords only when `netState === 'swing'`.
