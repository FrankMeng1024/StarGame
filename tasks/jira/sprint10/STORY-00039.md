# STORY-00039: 场景介绍时机修复

**Epic**: E-010 新迭代改进
**Sprint**: Sprint 10
**Sprint Goal**: 核心游戏体验升级
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, I want the scene name intro overlay to feel like a scene-transition ceremony (shown before the game begins), not something that appears on top of the game mid-play.

## Expected Result
The scene intro overlay shows correctly as a full-screen interstitial. The game loop does NOT start until the intro completes. `lastTick` is reset after intro so no timer drain occurs during intro. The intro never shows again for the same scene after the first visit.

## Acceptance Criteria
- [ ] Scene intro (e.g. "特卡波湖·牧羊人小屋") shows ONLY on first entry to each scene group (levels 1, 6, 11, 16, 21, 26)
- [ ] During the intro animation, the game loop has NOT started — timer is frozen, no stars/debris visible
- [ ] `lastTick` is reset to `performance.now()` at the moment `onDone()` is called (after intro completes)
- [ ] The intro overlay shows the location name in large text + scene number range "第 N–N 关"
- [ ] After intro fades out, game starts cleanly with full timer remaining (no timer drain during intro)
- [ ] On revisit to a level in the same session (seenScenes already contains sceneIdx), no intro shown — goes directly to game
- [ ] Across sessions (seenScenes persisted in localStorage), no intro shown on revisit
- [ ] Zero console errors during intro → game transition

## Notes
Current behavior investigation needed: the bug report says "进入游戏是猎户座关卡，但是进入瞬间显示 特卡波湖 小屋". This suggests either:
1. `seenScenes` is not persisting correctly across sessions (scene always appears "unseen"), OR
2. The intro IS showing correctly for first visit but the user found it jarring because the game canvas is visible behind it

The `_introPlaying = true` guard and `lastTick` reset at intro completion (`this.lastTick = performance.now()`) were added in Sprint 7 as rules. Verify these are implemented correctly in the current code. If `seenScenes` persistence is the issue, check `state.save()` is called after adding the scene.

Primary fix target: ensure `lastTick` reset happens at `onDone()` call site, not before intro starts.
