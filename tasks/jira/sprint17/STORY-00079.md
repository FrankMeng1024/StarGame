# STORY-00079: 关卡资源预加载

**Epic**: E-017 游戏手感修复
**Sprint**: Sprint 17
**Sprint Goal**: 游戏手感全面修复
**Points**: 3
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a player, I want the level to appear immediately when I enter it, without a blank canvas flash while images load.

## Expected Result
When navigating to a level, the game canvas renders immediately with all sprites visible. No blank/partially-rendered canvas flash.

## Acceptance Criteria
- [ ] Entering a level from the level select shows no blank canvas flash — girl sprite and net sprite appear on first rendered frame
- [ ] Level starts only after girl.svg and net.svg are confirmed loaded (both `_charImgReady` and `_netImgReady` true before first draw)
- [ ] Loading does not block UI thread — a brief "加载中..." overlay or the existing intro overlay covers the canvas during the load wait
- [ ] Load time under 500ms (assets are local, should be near-instant) — game starts within 500ms of navigation
- [ ] Zero console errors during load/start sequence

## Notes
Root cause: `GameEngine` constructor starts the RAF game loop immediately (calls `start()` at end of `game.js` `startGame()`). At this point, `_charImgReady` and `_netImgReady` may be false because Image.onload is asynchronous. The engine already has fallback procedural drawing, so it renders — but the SVG sprites appear on the second or third frame.

Fix approach:
1. In `GameEngine`, don't call `start()` immediately — call `_preload()` instead
2. `_preload()`: create both Image objects, attach onload handlers. When BOTH are loaded (or after 400ms timeout to not stall indefinitely), call `start()`
3. The intro overlay (`_introPlaying`) already covers the first few frames — coordinate timing so intro shows while loading completes
4. Alternative simpler approach: start the RAF loop immediately but delay `_introPlaying = false` until both images are ready OR 400ms elapsed — the intro overlay already masks the blank frames

The simplest correct fix: in `startGame()` in `game.js`, before creating GameEngine, preload both assets (girl.svg, net.svg) using Promise-based Image loading, then create+start the engine only after both resolve (or 400ms timeout).
