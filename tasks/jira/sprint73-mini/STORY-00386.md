## Notes
**Root cause**: Buttons were drawn inside `ctx.translate(0, cardSlideY)` transform. `drawButton()` stored pre-translate Y coords. Touch events arrive in screen coords. Old fix (STORY-00382) compensated via `rty = ty - _cardSlideY` in `_onTouch`, but this created a secondary bug: during the entrance animation (first 500ms), `_cardSlideY > 0`, so `rty` undershot the button Y (e.g. ty=336, _cardSlideY=5, rty=331 → hitTest pass; but during animation ty arrives at visual position 336 and btn.y=331+slide=336, rty=331 which misses by 5px). Additionally, debug timers ([DEBUG-386] 300ms forced-fail + 2.5s auto-navigate) were creating a loop that made it appear buttons were broken.

**Fix (STORY-00386)**: After `ctx.restore()`, update all button rects to screen coordinates by adding `cardSlideY` to their y values. Touch handler uses `ty` directly without compensation. This is correct because buttons now always reflect their true visual (screen) position. Applied to: `_btnNext`, `_btnRetry`, `_btnReplay`, `_btnLevels`, `_btnLoreNext`.

**Evidence**: docs/qa/sprint73-evidence/STORY-00386-02-fail.png — fail result screen with 重试/选关 buttons visible. Console shows `navigate:levels` confirming 选关 navigation worked.
