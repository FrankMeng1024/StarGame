# STORY-00302: 展厅闪烁BUG修复 + 展厅返回菜单

**Epic**: Mini端真机质量修复
**Sprint**: Sprint 30-mini
**Sprint Goal**: 修复3个Blocker级真机bug
**Points**: 2
**Owner**: Frontend Dev
**Status**: Done

## Description
As a player, when I tap "看展厅" on the victory screen, I want the gallery to open cleanly without flickering, and when I tap back in gallery, I want to return to the main menu (not the level select screen).

## Expected Result
1. 点击"看展厅"后：屏幕平滑过渡到星座展厅，不出现角色+展厅交替闪烁
2. 展厅列表页点击"← 返回"：导航到主菜单（menu），不是关卡选择（levels）

## Acceptance Criteria
- [ ] **BUG-A (闪烁)**: 从胜利结算卡点击"看展厅"→ 展厅画面干净显示，无game.js的角色/网兜残留帧
  - Root cause: `fadeNavigate(() => _navigate('gallery'))` 期间，game.js的RAF仍在运行绘制角色
  - Fix: `_navigate('gallery')` 调用时，立即调用 `hideGame()`（即在fadeNavigate的回调前后都stop game RAF）
  - 验证：Playwright截图展厅画面，不含角色Canvas绘制痕迹
- [ ] **BUG-B (返回路径)**: `gallery.js` 列表页返回按钮点击 → `_navigate('menu')` 而非 `_navigate('levels')`
  - 代码位置: `gallery.js:620`，当前为 `_navigate('levels')` → 改为 `_navigate('menu')`
  - 验证：Playwright操作：menu→gallery→back→确认到达menu页面（显示"挑战关卡"等按钮）
- [ ] 导航回归：menu→gallery→back→menu流程无JS报错
- [ ] 展厅进入后可正常滚动卡片，点击进入详情，详情内返回回到列表

## Notes
BUG-A根因：game.js中 `_rafId` 只在 `hideGame()` 中被取消。`fadeNavigate` 是异步的（有过渡动画），在过渡期间game的RAF仍然在绘制，导致gallery的Canvas内容和game的内容交替渲染产生闪烁。
修复方案：在 `_btnGallery` 点击处理中，`fadeNavigate` 回调改为先调用 `_cleanup()` 再navigate，或者在navigate函数中确保hideGame在showGallery之前同步执行（已有此逻辑但fadeNavigate绕过了）。
