## Description
As a QA engineer, I want a high-speed screenshot pipeline that captures 5 sequential frames at 100ms intervals and analyzes them with GLM-4V for animation issues, so I can detect transient bugs that single-frame screenshots miss.

## Expected Result
`scripts/mss_navigate.py` gains a `--burst N` mode that captures N frames at 100ms intervals at key states. `scripts/glm_analyze.py` gains multi-image "flipbook" support that outputs `animation_issues` field describing frame-to-frame state changes. Results written to `navigate-summary.json` `frame_analysis` field.

## Acceptance Criteria
- [x] `python scripts/mss_navigate.py --burst 5` captures 5 frames: `step-NN-frame-A.png` through `step-NN-frame-E.png` at the game/result step (mss_navigate.py:466-493)
- [x] `glm_burst_analyze()` accepts multiple image paths and outputs `animation_issues` array in JSON response (mss_navigate.py:495-531)
- [x] GLM failure (network/quota) gracefully degrades to single-frame mode (no crash, logs warning) (mss_navigate.py:520-527)
- [x] `navigate-summary.json` includes `frame_analysis` field when burst mode was used (mss_navigate.py:652-654)
- [x] Burst integrated at game screen step (lines 593-597) and fail screen step (lines 607-611)
- [x] Script runtime: burst capture of 5 frames adds ≤ 1 second (100ms × 5 frames = 500ms capture window)

**Notes**: All ACs verified by code read. Implementation was already complete from prior sprint. No new code needed.
