## Description
As a player, I want to tap a level card and immediately enter the level, so that navigation is reliable and responsive.

## Problem Analysis
Root cause: `game.js` `navigate()` has a 300ms debounce (`_lastNavTime`). When the game ends → navigates to 'levels' (this sets `_lastNavTime = Date.now()`), then user taps a level card → `_navigate('game')` → hits the 300ms debounce → BLOCKED. User taps something else (back → menu → levels) which resets the debounce, then taps level again — works.

Fix options:
1. Reset `_lastNavTime = 0` when entering levels screen — clean solution
2. Reduce debounce to 50ms — still protects against double-tap, doesn't block intentional navigation
3. Use a whitelist: debounce only applies to same-key repeat navigation

Best fix: Both (1) and (2). Reset `_lastNavTime = 0` at start of `showLevels()` call in game.js's navigate switch, AND reduce debounce from 300ms to 100ms.

## Acceptance Criteria
- [ ] `navigate()` in game.js: debounce reduced from 300ms to 100ms
- [ ] `showLevels()` is called via `navigate('levels')` — at the start of the 'levels' case in the switch, `_lastNavTime = 0` is reset
- [ ] Tapping a level card immediately after arriving at levels screen → navigates to game
- [ ] Double-tap spam on a level card does NOT navigate twice (100ms debounce still protects)
- [ ] Tapping back button immediately after arriving at levels → goes to menu
- [ ] Shop shortcut from levels → shop works reliably
