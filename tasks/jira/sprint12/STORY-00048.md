# STORY-00048: 道具系统功能验证与修复

**Epic**: E-003
**Sprint**: Sprint 12
**Sprint Goal**: 游戏玩法体验修复
**Points**: 5
**Owner**: Frontend Dev
**Status**: Todo

## Description
As a player, I want items I activate during gameplay to have clearly visible, real effects, so that buying and using items feels worthwhile.

## Expected Result
All 7 active items and 2 passive items produce their stated effects when activated. The item selection modal correctly shows owned items before level start.

## Acceptance Criteria
- [ ] Item selection modal appears when player clicks a level card AND has owned active items
- [ ] Modal correctly lists all owned active items with quantity
- [ ] Selecting item in modal assigns it to slot 1/2/3; pressing that key during game activates it
- [ ] **net_speed**: Net extension and retraction visibly faster for 15s after activation
- [ ] **star_magnet**: Stars within ~80px of net tip visibly drift toward it for 30s (observable in screenshot series)
- [ ] **shrink_debris**: All debris visibly smaller (50% size) for 30s after activation
- [ ] **space_bomb**: All debris disappears from canvas within 1 frame of activation
- [ ] **time_ext**: Timer increases by 20s immediately on activation (verifiable by reading timeLeft before/after)
- [ ] **glove**: Catching debris does NOT subtract time for 30s (time remains unchanged after debris catch)
- [ ] **double_coins**: Final coin award is exactly 2x what it would be without the item
- [ ] If no items owned, game starts directly without showing modal
- [ ] Passive items (double_coins) consumed at level start, not on activation
- [ ] Zero console errors throughout all item interactions

## Dependencies
- None

## Notes
Codebase analysis says all 7 items are implemented. But user reports "道具失效". Most likely issue: the item-select.js modal may fail to populate (wrong state access), OR the key 1/2/3 listener is not registered, OR `state.getItemQty()` returns 0 due to save format mismatch. Start by adding items via `window.__state.addItem('net_speed', 3)` and navigating the full flow to find where it breaks. Check both item-select.js and the key listener registration in engine.js or game.js.
